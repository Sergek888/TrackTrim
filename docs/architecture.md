# Architecture

## Main principle

Track — основная модель.

GPX — только формат сериализации.

Главный поток:

File
→ format.read()
→ Track
→ model statistics
→ UI

Будущий поток обрезки:

Track
→ application.proposeTrim()
→ TrimProposal
→ user confirmation
→ application.applyTrim()
→ Track
→ format.write()
→ download

## Modules

src/

    model/

    formats/

    application/

    komoot/

    ui/

## Responsibilities

model:
- содержит Track, TrackPoint, TrackStatistics
- содержит универсальные вычисления по треку
- может считать distance, duration, average speed
- Track при создании может хранить предрасчитанные накопленные значения для каждой точки:
  - elapsed time from start
  - distance from start
- накопленные значения являются частью model и доступны через точки Track
- сегментация по изменению средней скорости является универсальным методом Track
- алгоритм сегментации не знает про автомобиль, обрезку, пользователя или GPX
- intervals — будущая возможность модели, а не требование текущего этапа
- не знает про GPX, XML, UI, пользователя, автомобиль

formats:
- читает и пишет внешние форматы
- преобразует GPX в Track
- не считает статистику
- не принимает пользовательские решения

application:
- только оркестрирует пользовательские сценарии
- не считает distance/speed/statistics вручную
- вызывает методы model
- может появиться позже для proposeTrim/applyTrim
- не нужен для простой статистики

komoot:
- внутренняя библиотека для работы с Komoot API
- не знает про Track, TrackMeta, TrackSource, TrackPointInput, formats, application или ui
- возвращает только собственные DTO и реализует только API/transport/parsing Komoot
- не принимает решений приложения и не создает модели проекта

ui:
- только отображает состояние
- не парсит GPX
- не считает статистику
- не содержит бизнес-логику
- UI-компоненты делятся на container-компоненты и presentational-компоненты
- presentational-компоненты не вызывают formats/application/model-вычисления, а только получают готовые данные через props

## Placement rules

Если функция отвечает на вопрос "что можно вычислить по треку?" — она должна быть в model.

Если функция отвечает на вопрос "что предложить пользователю сделать?" — она должна быть в application.

Если функция отвечает на вопрос "как прочитать/записать файл?" — она должна быть в formats.

Если функция отвечает на вопрос "как показать пользователю?" — она должна быть в ui.

## Helper rules

- Helper не является самостоятельным архитектурным слоем.
- Helper должен быть минимальным по объему и иметь узкую техническую задачу.
- В helper можно выносить только маленькие функции, которые не образуют сущность, не относятся к существующей сущности и не тянут на отдельный модуль или библиотеку.
- Helper не должен становиться местом для несвязанной логики без общей цели.
- Если функция имеет предметный смысл, ее нужно относить к model, application, formats, ui или к существующей сущности.
- Если технический код начинает расти, нужно рассмотреть выделение целевого модуля или библиотеки вместо расширения helper.
- Новые сущности не создаются без необходимости.
- Если правило размещения выполнить нельзя, нужно сначала вынести на обсуждение варианты:
  - создать новую сущность;
  - отнести поведение к существующей сущности;
  - выделить целевой технический модуль или библиотеку;
  - оставить минимальный helper как временное решение.

## Change approval

- Никакие изменения в код нельзя вносить без явного подтверждения на конкретный шаг.
- Это правило действует для любых задач, включая рефакторинг, исправления, переименование и перенос файлов.
- Перед изменением кода нужно описать затрагиваемые файлы, цель изменения и что останется нетронутым.
- После подтверждения нужно выполнять только согласованный объем изменений.
- После каждой успешной доработки нужно делать коммит для GitHub.

## Restrictions

Track не должен знать:

- GPX
- XML
- UI
- автомобиль
- пользователя

UI не должен:

- анализировать трек
- парсить GPX
- изменять Track

## Map preview

- карта находится только в ui
- карта не читает GPX
- карта не анализирует Track
- карта не знает про время
- карта не знает про обрезку
- TrackMap получает готовый Track
- TrackMap только отображает данные
- любые производные Track создаются model
- исходный Track не мутируется

## Interactive map selection

- карта не принимает решений
- карта не ищет место обрезки
- карта не создает Track
- карта не мутирует Track
- карта только отображает готовые данные
- карта только генерирует пользовательское событие выбора
- Map -> selected coordinates
- selected coordinates -> model.closestPointIndex()
- производные Track создаются только model

## Track sources

- Track может хранить TrackMeta как паспорт трека в источнике.
- TrackMeta хранит живой экземпляр TrackSource и remoteId.
- TrackMeta делегирует внешние ссылки источнику через getOriginalUrl() и getShareUrl().
- Track не вызывает TrackSource напрямую и не знает про GPX, XML, API, авторизацию или скачивание.
- Производные Track сохраняют тот же TrackMeta.
- TrackSource является сущностью предметной области приложения: источник треков, его имя, порядок, видимость, цвет, список треков и внешние ссылки.
- TrackSource сейчас также содержит прикладное поведение загрузки и сохранения треков. Это осознанный компромисс текущего этапа: источник остается живым объектом, а технические детали отделяются точечно.
- Технические детали вроде HTTP-транспорта, чтения файлов, DOM-download и парсинга внешних ответов не являются моделью источника и могут выноситься в отдельные целевые модули без разделения TrackSource на поля и методы.
- Техническое взаимодействие с Komoot находится в komoot как автономная API-библиотека. KomootTrackSource адаптирует DTO этой библиотеки к TrackMeta и Track.
- LocalFileSource является текущей реализацией TrackSource для локального GPX.
- KomootTrackSource является будущей реализацией TrackSource для Komoot.
- Первый этап Komoot-интеграции работает от URL тура и создает TrackMeta без загруженного Track, если геометрия еще не получена.
- Загрузка геометрии Komoot включается только после проверки доступного GPX/JSON endpoint и CORS.
- UI вызывает источник через контракт и не работает с сырым GPX-текстом.
- TrackConverter находится в formats и переводит RawPayload в геометрию TrackPointInput[] и обратно.
- GpxConverter является текущей реализацией TrackConverter для GPX.
