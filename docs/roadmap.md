# Roadmap

## Current milestone: prepared track metadata

Текущий этап ограничен подготовкой базовых пользовательских характеристик в
`TrackMeta`: activity kind/type, difficulty, activity date, source update date,
distance, duration, elevation gain и elevation loss.

В этап не входят дополнительные запросы Komoot, surfaces, way types, POI,
highlights, photos, фильтры и сортировка.

## Deferred Komoot segmented data

Наблюдения подтверждены для текущего Komoot API-контракта на 2026-06-15.

- `/surfaces` и `/way_types` требуют отдельных запросов для каждого тура.
- Возвращаемые интервалы относятся к полной геометрии `/coordinates`.
- Упрощённая overview geometry, доступная в строках коллекции, недостаточна для
  корректной привязки этих интервалов.
- Eager-загрузка плохо масштабируется для коллекций и аккаунтов: количество запросов
  растёт пропорционально числу туров ещё до того, как пользователь открыл конкретный
  трек.
- Surfaces требуют закрытого предметного enum, явного mapping внешних значений и
  правила обработки пробелов между интервалами.
- Way types смешивают категории пути с техническими шкалами SAC/MTB, поэтому их нельзя
  моделировать одним плоским enum без отдельного анализа семантики.
- Для этих данных нужен будущий lazy-loading сценарий по выбранному треку и caching,
  учитывающий версию или дату изменения источника.
- POI, highlights и photos требуют отдельного анализа API, модели координатной
  привязки, прав доступа, объёма данных и UI.

До такого анализа segmented и content data не добавляются в `Track`, `TrackMeta` или
общие UI-компоненты.
