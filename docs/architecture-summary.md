# Architecture Summary

Короткий архитектурный контекст для Codex, AI-агентов и быстрых задач.

Полное описание: `docs/architecture.md`.

## Назначение

TrackViewer работает с геоданными независимо от источника, формата и способа отображения.

Базовый поток:

```text
External data → adapter → TrackSource → TrackMeta / Track → TrackLibrary → UI / Map
```

## Core principles

- Предметная модель не зависит от источников, форматов, HTTP, UI и внешних API.
- Внешние данные адаптируются к модели проекта, а не наоборот.
- Крупные зоны ответственности изолируются по причинам изменения.
- Простота важнее формальной чистоты.
- Новые сущности появляются только под давлением реальной задачи.
- Связанность не надо прятать интерфейсами, если ответственность всё равно общая.
- Универсальность создаётся после устойчивого повторения.
- UI не содержит предметных вычислений.
- Карта — крупная UI-зона, но не владелец бизнес-решений.

## Dependency direction

```text
ui → application → model
application → formats / integrations
formats → model contracts
integrations → own DTO / transport contracts
```

Запрещённое направление важнее структуры каталогов.

## Layer roles

| Layer | Role |
|---|---|
| `model` | Предметная модель и универсальные вычисления по геоданным |
| `formats` | Чтение и запись внешних форматов |
| `integrations` | Работа с внешними системами, DTO, transport, auth |
| `application` | Пользовательские сценарии, `TrackSource`, `TrackLibrary` |
| `ui` | Отображение данных и пользовательское взаимодействие |
| `api/*` | Server runtime adapters |

## Logic placement

| Вопрос | Где должна жить логика |
|---|---|
| Что можно вычислить по геоданным? | `model` |
| Как прочитать или записать формат? | `formats` |
| Как работать с внешней системой? | `integrations` |
| Как перевести внешние данные в модели проекта? | `TrackSource` |
| Как выполнить пользовательский сценарий? | `application` |
| Как показать данные пользователю? | `ui` |

## Stable domain notes

- `Track` immutable.
- Точки `Track` не изменяются после создания.
- Анализ, сегментация и редактирование создают новый `Track`.
- `TrackMeta` — единый контракт отображаемых характеристик для общего UI.
- `TrackPoint` различает абсолютное время `time` и время от начала `elapsedSec`.
- `TrackSource` представляет источник данных.
- `TrackLibrary` — центральное состояние рабочей области.

## UI rules

UI может форматировать готовые значения для отображения.

UI не должен вычислять характеристики геометрии, разбирать GPX/XML, знать DTO внешних API, принимать бизнес-решения или управлять runtime/transport деталями.

## Known compromises

- Связь `TrackMeta` с `TrackSource` — осознанный текущий компромисс.
- `TrackLibrary` сосредотачивает несколько ответственностей как упрощение текущего этапа.
- Некоторые аналитические поля `TrackMeta` временно заполняются расчётами только если источник их не предоставил.
