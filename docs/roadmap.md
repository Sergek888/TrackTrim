# Roadmap

## Current milestone: prepared track metadata

Текущий этап ограничен подготовкой базовых пользовательских характеристик в `TrackMeta`.

В scope этапа входят: activity kind/type, difficulty, activity date, source update date, distance, duration, elevation gain, elevation loss.

В этап не входят: дополнительные запросы Komoot, surfaces, way types, POI, highlights, photos, фильтры, сортировка.

## Deferred Komoot segmented data

Наблюдения подтверждены для текущего Komoot API-контракта на 2026-06-15.

- `/surfaces` и `/way_types` требуют отдельных запросов для каждого тура.
- Возвращаемые интервалы относятся к полной геометрии `/coordinates`.
- Упрощённая overview geometry, доступная в строках коллекции, недостаточна для корректной привязки этих интервалов.
- Eager loading плохо масштабируется для коллекций и аккаунтов: количество запросов растёт пропорционально числу туров ещё до открытия конкретного трека.
- Surfaces требуют закрытого предметного enum, явного mapping внешних значений и правила обработки пробелов между интервалами.
- Way types смешивают категории пути с техническими шкалами SAC/MTB, поэтому их нельзя моделировать одним плоским enum без отдельного анализа семантики.
- Для этих данных нужен будущий lazy-loading сценарий по выбранному треку.
- Нужен caching, учитывающий версию или дату изменения источника.
- POI, highlights и photos требуют отдельного анализа API, модели координатной привязки, прав доступа, объёма данных и UI.

До такого анализа segmented и content data не добавляются в `Track`, `TrackMeta` или общие UI-компоненты.

## Future candidates

### Additional sources

Возможные будущие источники: другие сервисы GPS-треков, локальные каталоги файлов, внешние системы хранения, импорт из ссылок.

Каждый новый источник должен добавляться через `TrackSource` и не менять модель проекта под особенности внешнего API.

### Additional formats

Возможные форматы: FIT, TCX, GeoJSON export/import, другие форматы маршрутов.

Каждый формат должен жить в `formats` и не управлять пользовательскими сценариями.

### Analysis and editing

Будущее направление, не текущий scope: анализ, сегментация, обрезка, редактирование геометрии, preview изменений, подтверждение изменений перед экспортом.

Эти функции должны создавать производные версии `Track`, не мутируя исходный объект.

### POI, photos and highlights

Отдельное будущее направление: точки интереса, фотографии, highlights, связь с OSM/Wikidata/внешними источниками.

Перед добавлением нужна отдельная модель координатной привязки и правила источника данных.

## Roadmap rule

Нельзя добавлять deferred-функции в `Track`, `TrackMeta` или общий UI только потому, что внешний API уже отдаёт эти данные.

Сначала сценарий. Потом модель. Потом UI.
