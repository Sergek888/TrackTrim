# Two-step workflow for Codex

Цель — не заставлять агента каждый раз сканировать весь проект.

## Problem

Плохой запрос:

```text
Проанализируй проект и исправь ошибку.
```

Так агент почти неизбежно начнёт читать слишком много.

## Better workflow

### Step 1 — navigation only

```text
Следуй AGENTS.md.

Сначала прочитай только:

- docs/architecture-summary.md
- docs/project-map.md

Не открывай код.

Назови минимальный набор файлов для задачи:
<описание задачи>
```

### Step 2 — targeted read and change

```text
Теперь открой только перечисленные файлы.

Не расширяй scope без объяснения.

Внеси изменение:
<описание задачи>
```

## When to use

Использовать всегда, если задача затрагивает несколько слоёв, непонятно где лежит нужная логика, может задеть архитектуру, связана с Komoot, связана с TrackLibrary/TrackSource/TrackMeta или потенциально требует чтения документации.

Можно не использовать для простого CSS-изменения, переименования текста или очевидного исправления в одном файле.

## Why this works

Агент сначала выбирает границы задачи, а не начинает читать проект. Это снижает лишнее чтение, случайные изменения рядом, повторное перечитывание полной архитектуры, расход токенов и риск архитектурных фантазий.
