# AGENTS.md

## Mission

TrackViewer — приложение для просмотра и организации GPS-треков из разных источников.

Цель агента — вносить минимальные точные изменения без лишнего сканирования репозитория и без размывания архитектурных границ.

## Default reading order

Перед задачей читай только минимальный контекст:

1. `docs/architecture-summary.md`
2. `docs/project-map.md`
3. Файлы, прямо связанные с задачей

Читать по необходимости:

- `docs/product.md` — если задача меняет пользовательский сценарий, scope или поведение продукта;
- `docs/roadmap.md` — если задача касается отложенных функций или планирования;
- `docs/architecture.md` — если задача меняет архитектурные границы, модель, интеграции или крупные потоки данных.

Не перечитывай полный проект без причины.

## Scope control

Перед изменением кода сначала определи минимальный набор файлов.

Если задача сформулирована широко, сначала перечисли предполагаемые файлы и зоны проекта.

Не расширяй scope молча. Если нужно открыть дополнительные файлы, кратко объясни почему.

## Hard constraints

- UI не содержит предметных вычислений по геоданным.
- UI не разбирает внешние форматы.
- UI не знает детали внешних API.
- `model` не зависит от UI, HTTP, GPX, Komoot и runtime-адаптеров.
- `formats` отвечают только за чтение и запись внешних форматов.
- `integrations` изолируют DTO, transport, auth, ошибки и особенности внешней системы.
- Новые сущности, слои, registry, service factory и event bus не добавляются без реальной причины.
- Простая реализация предпочтительнее преждевременной универсальности.
- Не создавать классы ради структуры, если достаточно простых типов и функций.
- Не менять архитектуру ради красоты каталогов.

## TrackViewer-specific rules

- `Track` immutable.
- Производные версии `Track` создают новый объект, исходный объект не мутируется.
- `TrackMeta` — единый контракт отображаемых характеристик для общего UI.
- Значения, пришедшие от источника, не перезаписываются расчётами без явного решения.
- `TrackSource` отвечает за загрузку, экспорт, внешние ссылки и операции источника.
- `TrackLibrary` остаётся центральным состоянием рабочей области.
- Komoot API, DTO, transport и fallback-логика принадлежат `src/komoot`.
- `api/komoot` содержит только server runtime adapters и ограниченный proxy.

## Testing

Запускай минимальную проверку, соответствующую задаче.

Порядок: target tests → typecheck/build → полный test suite только если изменены общие контракты или инфраструктура.

Если команды неизвестны, сначала посмотри `package.json`.

## Output format

В ответе кратко укажи: что изменено, какие файлы затронуты, какие проверки выполнены, что не проверялось и почему.

Не пересказывай весь проект.
